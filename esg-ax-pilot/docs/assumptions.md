# 가정 사항 (Assumptions)

업무 담당자 확인 전까지 개발 편의를 위해 둔 가정이다. 확정되면 해당 항목을 갱신한다.

## 단계 1 — 골격·DB·샘플 데이터

| # | 가정 | 교체 방법 / 확인 필요 |
|---|---|---|
| A1 | 프로젝트는 기존 정적 대시보드 저장소(`triplej`) 안의 `esg-ax-pilot/` 하위 폴더에 둔다. | 별도 저장소로 분리할지 확인 |
| A2 | `suppliers` 컬럼: 회사명·업종·국가(ISO 2자리)·연간 거래규모(백만원, 정수)·거래유형(직접재/간접재/외주가공/서비스)·담당자 이메일(마스킹). 매핑 안 된 원본 컬럼은 `extra`(JSON)에 보존. | `[TBD]` Click ESG 컬럼 매핑 — 단계 2에서 설정 파일로 분리 |
| A3 | 샘플 협력사 20곳은 seed 고정 난수로 생성(`data/samples/suppliers_sample.csv`). 회사명은 `협력사-001` 형식, 이메일은 `example.com`으로 익명화. 업종·국가·거래규모는 실제 분포가 아님. | 실제 익명화본으로 교체 |
| A4 | 진단 케이스는 협력사×진단연도(기본 2026) 당 1건, `case_id = C{연도}-{supplier_id}`. 적재 시 상태 `IMPORTED`. | |
| A5 | 자가진단 응답 기한(`cases.saq_due_date`)을 추가함. 운영 Agent의 "기한 초과 미응답" 점검에 필요. 샘플 기본값은 연초+300일. | 실제 기한 정책 확인 |
| A6 | SPEC 10장(비용 관리)을 위해 `llm_usage` 테이블을 추가함(토큰·추정 비용). | |
| A7 | `audit_log`에 `case_id`, `from_status`, `to_status` 컬럼을 명시적으로 둠(SPEC 4장 "이전/이후 상태"). | |
| A8 | Enum 값은 SPEC 표기 그대로 저장(판정 `적합/불일치/증빙누락/확인필요`, 우선순위 `상/중/하`, 승인 `승인/반려`). PostgreSQL 전환을 위해 DB 네이티브 ENUM 대신 VARCHAR로 저장. | |
| A9 | `[TBD]` 기준 파일(Risk Tier 기준표, 문항 목록, 배점표, BP 라이브러리)은 `data/reference/*.yaml` 경로로 `config.REFERENCE_FILES`에 등록만 해 둠. 샘플 파일은 해당 단계(4·5·7)에서 생성. | 담당자 자료 수령 시 파일만 교체 |
